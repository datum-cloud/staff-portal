# 05 · Error Handling & Reporting

How the staff portal models errors, surfaces them to users, logs them, and
reports them to Sentry. Read this before touching error flows, the axios
interceptors, or Sentry wiring.

---

## 1. The error model — `app/utils/errors/`

- **`base.ts` → `AppError`** — an `Error` subclass carrying `statusCode`,
  `code`, and `requestId`, plus `toResponse()` which serializes
  `{ message, error: name, requestId }` into a JSON `Response`
  (`status = statusCode`, `statusText = code`).
- **`http.ts`** — `HttpError`, `BadRequestError` (400), `NotFoundError` (404),
  `ValidationError` (422), `ConflictError` (409).
- **`auth.ts`** — `TokenError` (401), `AuthenticationError` (401,
  `AUTH_ERROR`), `AuthorizationError` (403, `FORBIDDEN`).
- **`error-mapper.ts` → `mapApiError(error, requestId)`** — the normalizer.
  Turns any raw error into the right typed `AppError`:
  - `AxiosError` → by `response.status` (400/401/403/404/409 → the matching
    subclass, else `HttpError`).
  - gqlts-style responses (`isGqlError`) and `@urql/core` `CombinedError` → by
    `extensions.code` (`UNAUTHENTICATED`/`FORBIDDEN`/`NOT_FOUND`/`BAD_USER_INPUT`).
  - plain `Error`/unknown → `AppError` with `INTERNAL_ERROR`/`UNKNOWN_ERROR`.
- **`error-parser.ts` → `parseK8sMessage(raw)`** — humanizes Kubernetes Status
  messages for display: strips admission-webhook prefixes and resource-path
  segments, and rewrites `kind.group "name" not found` via the shared resource
  label map. Message normalization only — it does not affect reporting.

> `error-mapper.ts` is imported directly (`@/utils/errors/error-mapper`); it is
> not re-exported from `errors/index.ts` (which exports base/auth/http/parser).

## 2. How errors flow

**Client axios — `app/modules/axios/axios.client.ts`** (`baseURL: /api/internal`)
- Response-error interceptor: on **401 with `data.code === 'AUTH_ERROR'`** it
  redirects to `/logout`.
- Extracts a message from many response shapes (`error`/`message`/`detail`/…)
  plus `requestId`, then runs it through `parseK8sMessage`.
- Calls **`captureApiError`** (→ Sentry) with url/method/status/requestId/
  responseData, and **always** shows a `toast.error`.

**Server axios — `app/modules/axios/axios.server.ts`** (`baseURL: env.API_URL`)
- Request interceptor injects `X-Request-ID` from an `AsyncLocalStorage`
  request context.
- Response-error interceptor logs the failure, calls `captureApiError`, then a
  `switch (status)` **throws a typed `AppError`** (`AuthenticationError` /
  `AuthorizationError` / `NotFoundError` / `ValidationError` / `HttpError`).

**Server (Hono) request handling**
- No global `app.onError`; each middleware/route wraps in try/catch and calls
  `logApiError` (structured log) + `captureApiError` (Sentry) +
  `createErrorResponse`.
- `requestId` is generated by `requestId()` middleware, stored in
  `AsyncLocalStorage`, injected into upstream calls, and surfaced on error
  responses and in the UI.

**React Router**
- `app/entry.server.tsx` exports `handleError = Sentry.createSentryHandleError(...)`
  for loader/action errors, and wraps the request handler with
  `Sentry.wrapSentryHandleRequest`. Local `onError`/`onShellError` only log.
- `app/root.tsx` `ErrorBoundary`: `AUTH_ERROR` route errors render `<AuthError>`
  (auto-redirects to `/logout`); a plain `Error` reaching the boundary is
  `Sentry.captureException`'d and shows `<GenericError>`; `RouteErrorResponse`s
  (404s / thrown Responses) are **not** captured.

**User-facing surfaces**
- Toasts: automatic only from the client axios interceptor; elsewhere manual.
- Components: `components/error/generic.tsx` (`GenericError`),
  `components/error/auth.tsx` (`AuthError`), `components/message-card`
  (`MessageCard`). Static error pages under `app/routes/error/*`.

## 3. Sentry integration

**Instance & environments.** Sentry is **self-hosted** (`org: 'sentry'`, host
`sentry.prod.env.datum.net`, running in the `sentry-system` cluster).
staff-portal is Sentry **project 2**. There is **one DSN**; every environment
sends to the same host and is separated only by `SENTRY_ENV`. Infra sets the
DSN + `SENTRY_ENV` per overlay in `datum-cloud/infra`
(`apps/staff-portal/<env>/patch-deployment.yaml`): preview = `${PREVIEW_NS}`,
`staging`, `production`.

**Two init sites** (a change to Sentry behavior usually has to touch both):
- **Client** — `app/entry.client.tsx`: `dsn`/`environment`/`release`,
  `sendDefaultPii: true`, React-Router tracing + replay integrations,
  `tracesSampleRate` 0.1 (prod) / 1.0 (else), replay 0.1 / on-error 1.0. No
  `beforeSend`.
- **Server** — `observability/providers/sentry.ts`, a `SentryProvider extends
  BaseProvider` started at boot by `observability/start.js` /
  `dev-start.js` (**not** `entry.server.tsx`). Includes a circuit-breaker
  `beforeSend` (drops events while open; otherwise passes them through
  unchanged) and Sentry self-error detection so the observability layer swallows
  Sentry's own failures.

**Capture path — `app/utils/logger/sentry.ts`** (the main one):
- `captureApiError(error, { url, method, status, requestId, responseData })` —
  adds a breadcrumb, sets `error.*` tags, and `Sentry.captureException(error, …)`
  with `responseData` in `extra`. Called from both axios interceptors.
- `setSentryUser(user)` / `clearSentryUser()` — sets `Sentry.setUser` plus a
  `user.*` tag per field and a `user` context; wired to user-state changes in
  `app/providers/app.provider.tsx`.
- Also: `addSentryBreadcrumb`, `setSentryTag`, `setSentryContext`. All are
  re-exported from `@/utils/logger`.

**Sourcemaps.** The `sentryReactRouter` vite plugin uploads hidden sourcemaps at
build time — `org`/`project: 'staff-portal'`/`authToken: SENTRY_AUTH_TOKEN`
(CI secret)/`release: VERSION` — gated to `NODE_ENV === 'production' &&
VERSION.includes('main')` (`app/utils/config/sentry.config.ts`,
`vite.config.ts`; `sentryOnBuildEnd` in `react-router.config.ts`). Runtime
`release` (`VERSION`) must match the upload release for events to resolve to
source.

**Config / env.** `app/utils/config/env.server.ts` validates `SENTRY_DSN` /
`SENTRY_ENV` and derives `isSentryEnabled` / `sentryUiUrl`; the root loader
exposes `SENTRY_DSN` / `SENTRY_ENV` / `SENTRY_UI_URL` to `window.ENV`
(`useEnv()`). Separate `SENTRY_API_*` vars power the chatbot's Sentry tool
(below), not reporting.

## 4. Logging (and its relationship to Sentry)

- `app/utils/logger/` — a `Logger` class (JSON, Bun-optimized, level-based,
  child/context loggers) plus `log.*` helpers and
  `createRequestLogger`/`createUserLogger`/`createSessionLogger`. Console-only;
  it does **not** call Sentry. `@/utils/logger` also re-exports the Sentry
  helpers, so it's the single import surface for both.
- `app/server/logger.ts` — `logApiError(logger, error, context)` classifies
  `AppError` / `AxiosError` / `Response` / `Error` into structured
  `ApiErrorDetails` and logs them. **Logging is decoupled from Sentry**: server
  routes call `logApiError` and `captureApiError` side by side.

---

## 5. Sentry as a chatbot data source (separate from reporting)

`app/modules/assistant/tools/sentry-tools.ts` queries the Sentry **REST API**
(`sentryApi()`, using `SENTRY_API_URL` / `SENTRY_API_TOKEN` /
`SENTRY_ORGANIZATION` / `SENTRY_EXCLUDED_PROJECTS`) so the assistant can read
issues. This is unrelated to how the app *reports* errors.
`getSentryIssuesUrl(SENTRY_UI_URL, userId)` builds Sentry deep-links in the UI.

## 6. Known limitations & caveats

Worth knowing when working in this area (all current, factual):

- **No PII/secret scrubbing.** `sendDefaultPii: true` on both inits;
  `setSentryUser` sends email + ~10 user fields as tags/context;
  `captureApiError` puts raw `responseData` into Sentry `extra`.
- **`beforeSend` does no filtering.** The server one is a circuit breaker only;
  the client has none. Every caught 4xx and bot 405 reaches the shared project.
- **`captureApiError` sets `error.*` tags on the global scope** (via
  `Sentry.setTag`, not `withScope`), so they can bleed onto later events.
- **No fingerprinting / report-gating / `ignoreErrors` / `denyUrls`.**
- **`axios.server.ts` 401 handling can fall through to 403** — the 401 branch
  has sub-cases without a `break`.
- **GraphQL proxy errors** (`app/server/routes/graphql.ts`) `console.error` and
  return 502/499, bypassing Sentry and the structured logger.
- **`/test-sentry`** (`app/routes/test-sentry.tsx`, registered in `routes.ts`)
  ships in production builds.
